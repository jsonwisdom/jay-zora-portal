# Jay Zora Portal — GitHub Governance Replay v0.1

**Classification:** repository governance / evidence-surface controls only  
**Canonical branch:** `live-zora-ingestion`  
**Authority created:** `false`

## Why this exists

This repository is a public proof surface. A green workflow, a bot commit, a draft PR, a mergeable flag, and a human approval are different states and must not be collapsed.

## Incident / replay anchor — 2026-08-18

PR #6 (`agent/zora-metrics-living-ledger-v0-3`) triggered `Export Zora Inventory CSV` on the `pull_request` event.

The workflow configuration at the time:

1. listened to `pull_request` targeting `live-zora-ingestion`,
2. declared `contents: write`,
3. explicitly checked out `ref: live-zora-ingestion` rather than the pull-request head,
4. generated an inventory manifest,
5. committed and pushed the generated files directly to `live-zora-ingestion`.

The PR-triggered run succeeded, but that success classified the checked-out canonical inventory path; it did **not** establish that PR #6's changed evidence leaves/proof file had been validated by that workflow.

The resulting bot commit advanced the canonical branch from `c5f5074ed525e57c01f1703e076be18ecc6dd1a9` to `177f297d00042b80ca66d1feb81f96c6659d8909` while PR #6 remained unmerged.

PR_TRIGGER != PR_VALIDATION

## Proposed control model

### G1 — Pull-request validation is read-only

`validate-pr-governance.yml`:

- event: `pull_request`
- token: `contents: read`
- checkout: exact `${{ github.event.pull_request.head.sha }}`
- base gate: `origin/live-zora-ingestion` must be an ancestor of the PR head
- runs deterministic governance checks
- parses evidence JSON surfaces
- never pushes a ref

### G2 — Inventory export is artifact-only

`export-zora-inventory.yml`:

- no `pull_request` trigger
- token: `contents: read`
- may build CSV + manifest
- may upload an Actions artifact
- may not commit or push to `live-zora-ingestion`

If generated bytes are to become Git history, they must be promoted in an explicit branch/PR flow.

### G3 — Governance-sensitive ownership is explicit

`.github/CODEOWNERS` names ownership for workflows, data, leaves, proofs, and canonical doctrine.

This documents review responsibility only. It becomes enforcement only when GitHub branch protection/rulesets require the corresponding review behavior.

### G4 — Machine governance verifier

`tools/verify-governance.mjs` fails when it observes:

- a `pull_request` workflow with `contents: write`,
- a PR workflow hard-checking out `live-zora-ingestion`,
- any workflow performing an automated `git push` to the canonical branch,
- missing governance-sensitive CODEOWNERS paths,
- a PR validator that is not exact-head, read-only, and base-synchronized.

## Current provider-level governance state observed before this proposal

- default branch: `live-zora-ingestion`
- branch protection: **disabled**
- required status checks at branch level: **not enforced by classic protection**
- PR #6: open / draft / unmerged
- PR #6 reviews observed: none
- repository auto-merge: disabled
- repository permits merge commits, squash merges, and rebase merges
- update-branch button/API support reported disabled by repository metadata
- latest canonical bot commit observed as unsigned

Provider-level settings are not changed by this document. A GitHub ruleset / branch-protection change is a separate authority-bearing repository setting action.

## Recommended provider ruleset after the workflow fix is canonical

For `live-zora-ingestion`:

1. require a pull request before human-authored code/evidence promotion,
2. require the read-only exact-head governance check,
3. require branch to be up to date before merge,
4. block force pushes,
5. block branch deletion,
6. require conversation resolution when review threads exist,
7. do **not** require signed commits until the automation/signing path is deliberately designed,
8. do **not** require a second-party approval unless a real independent reviewer exists; a solo-owner repository should not create a self-deadlocking rule.

## Merge authority

No branch, workflow, CODEOWNERS file, status check, or assistant action creates merge authority.

```text
INTENT != READY
READY != MERGED
MERGEABLE != MERGED
AUTOMATION != APPROVER
MERGE_REQUIRES_EXPLICIT_JAY_ACTION
```
